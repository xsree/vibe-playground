# 总览

> 本文档用于指导 AI 生成「网页版 PS5 DualSense 手柄」交互页面。
> 素材参考来源：DrawGPT Canvas 绘制法、PromptsZone DualSense 造型描述、
> virtual-gamepad-lib 的 SVG 交互规则、Tobias Wetzel 的控制器动画架构。

---

## 一、一句话需求

用纯前端（HTML/CSS/JS、零构建）制作一个**高保真、可交互的 PS5 DualSense 网页版手柄**，打开即用。

---

## 二、核心提示词

```text
请用纯原生前端（单文件 HTML + 内嵌 CSS + 内嵌 JS，禁止外部依赖、禁止构建、无需网络即可打开）制作一个可交互的网页版「PS5 DualSense 手柄」。

【视觉要求】
- 采用 SVG + CSS 绘制手柄本体，白色主体 + 深色握把（DualSense 经典黑白配色）。
- 画面居中，深色渐变背景（适合展示手柄的金属/哑光质感），整体精工质感、线条清晰。
- 支持深色主题界面配套；不依赖任何图片素材，全部矢量绘制。

【必须包含的部件】
1. 手柄主体：对称双握把、中央大触控板（Touchpad，白色带四角微圆弧）。
2. 十字方向键 D-Pad（左上，四向）。
3. 右侧四个功能键：△ 三角（上）、○ 圆圈（右）、✕ 叉（下）、□ 方块（左），按键旁带对应符号。
4. 左右两枚摇杆（Analog Stick，位于触控板下方左右，带内凹纹理，可点击 L3/R3）。
5. 肩键 L1/R1 与扳机 L2/R2（顶部）。
6. 中央「PS」圆形 Logo 键、左右 Options / Create 键。
7. 手柄下方一条彩色灯带（Light Bar，默认蓝色，按下按钮时可变色点缀）。

【交互要求】
- 鼠标悬停 / 点击任意按键：按键高亮或按下（translate 下沉 + 颜色变化），松手回弹（平滑 transition）。
- 摇杆可拖动（鼠标/触摸），杆头随指针位移，松手回弹回中心；拖动时对应 L3/R3 状态点亮。
- 触控板可点击，按下时凹陷并显示高亮，显示按压坐标反馈。
- 按下扳机 L2/R2：以透明度/位移体现按压深度（0–100% 模拟量）。
- 所有交互都应有即时视觉反馈，按钮响应要有「按下→回弹」的物理感。

【技术规范】
- 单文件、可离线打开；所有样式与脚本内联在一个 .html 里。
- 元素使用命名 id，方便后续用 Gamepad API / WebHID 扩展真实手柄输入。
- 适配移动端（响应式缩放、触摸支持）。
- 允许用户拖动旋转整个手柄（可选加分项）。
```

## 三、测试规范说明

1. **保存位置**：必须保存在工作区下新建的`web-ps5-controller`文件夹内（而非工作区根目录或其他路径）。
2. **文件命名（模板）**：`harness-llm-resoningeffort`
   - 其中 `harness` / `llm` / `resoningeffort` 为**占位符**，实例化时填入被测 agent 的真实身份。
   - 示例：`opencode-nemotron-3-ultra-free`（harness=opencode，llm=nemotron-3-ultra-free）
   - 推理 effort 默认标记为 `high`（除非 llm 知道自己的思考强度或用户提示 llm 当前思考强度时）
   - 模型名和 harness 名由被测 agent 自行填写自己的真实身份，不得留空或写 "unknown"。
   - 扩展名按实际产出类型定：本页产物为单文件交互页面，用 `.html`。
3. **交付要求**：生成后必须以可预览的方式展示给用户（预览面板 / 文件卡片 / 浏览器打开），不能只回复"已完成"。
4. **内容要求**：纯手写矢量代码（不允许调用图像生成模型生成位图）；画面须完整呈现 PS5 DualSense 手柄主体及其核心部件（双握把、触控板、D-Pad、△○✕□、双摇杆、肩键/扳机、PS 键、灯带），比例合理、语义清晰可辨认。
5. **独立创作约束（重要）**：创建产物时，**不得参考、读取、借鉴当前目录下任何已存在的文件**（包括本文档"已有结果"中列出的历史产物）。必须完全独立地从头构思与绘制，以保证跨模型对比的公平性。若为满足文件命名规范而需要读取目录清单，仅允许读取文件列表。
