# 完整作品要求（已同步自由视角与持续循环）
请创建一个可直接在浏览器运行的高质量 3D 网页作品，效果参考“日系春季铁路车站微缩模型 / Japanese railway miniature diorama”。

这是一个视觉作品，不是 Three.js 教程，不要为了减少代码量而牺牲视觉完成度。

只允许创建 3 个文件：

* index.html
* style.css
* main.js

作品目录禁止创建任何其他文件。允许在`3d-spring-railway-diorama`父目录保存测试提示词与启动脚本。启动脚本只使用 Python 或 Node.js 标准库，不依赖 npm 包或构建工具。

* 使用 Three.js
* Three.js 通过 CDN ES Module / importmap 引入
* 可以使用 Three.js 官方 addons，例如 OrbitControls、EffectComposer、UnrealBloomPass 等
* 不使用 React
* 不使用 Vue
* 不使用 Svelte
* 不使用 TypeScript

## 一、整体目标

创建一个悬浮在空中的精致日系铁路微缩沙盘。

整体视觉风格：

Japanese miniature diorama
stylized 3D
low-poly
toy-like miniature
pastel colors
spring atmosphere
cherry blossom railway station
cozy game environment
clean geometry
soft PBR materials
soft shadows
ambient occlusion
isometric diorama
cinematic camera
highly detailed miniature environment

整体应该像一件精致的日本铁路建筑模型、游戏场景或收藏级微缩沙盘，而不是写实摄影。

可以参考以下视觉方向：

* Nintendo 式清爽卡通 3D
* Animal Crossing 式微缩世界
* 日系建筑模型
* Low-poly game environment
* Toy-like architectural visualization

不要使用过于真实、脏旧、阴暗的材质。

画面应该明亮、干净、柔和、治愈，同时有足够丰富的细节。

## 二、沙盘结构

整个 3D 世界位于一个悬浮的正方形或略微长方形沙盘底座上。

沙盘底部有一定厚度，并带轻微倒角感。

沙盘之外不放置无限地面。

背景保持简洁，使整个场景明显像悬浮的微缩模型。

建议整体布局：

一侧是绿色山丘和铁路隧道。

铁路从隧道中出来，经过道口，然后进入中央车站区域。

铁路另一侧分布住宅、道路、樱花树、电线杆、自行车棚等细节。

所有区域在俯视状态下都应该有良好的构图，而不是随机摆放。

---

## 三、铁路系统

建立两条平行铁路轨道。

铁路需要包含明显的结构层级：

* 两根钢轨
* 大量枕木
* 碎石道床
* 铁路边缘
* 简单排水沟或路基结构

枕木必须沿轨道规律排列。

轨道不能只使用两条简单直线。

即使整体铁路较直，也应该有真实的层次和比例。

铁轨颜色以深灰、金属灰为主。

枕木使用深棕色或灰褐色。

碎石道床使用浅灰色。

---

## 四、火车

创建一辆完整的日系通勤列车。

列车至少有 2～3 节车厢。

不要只使用一个长方体作为火车。

每节车厢应包含：

* 主车体
* 车顶
* 前后驾驶室
* 前挡风玻璃
* 侧窗
* 车门
* 车头灯
* 尾灯
* 底盘
* 简化转向架
* 简化车轮
* 车厢连接结构

列车整体使用白色或浅灰色车身。

增加粉色和青绿色装饰线条，使其符合春季日系铁路视觉风格。

车窗使用略深、带轻微反射感的材质。

车头造型应尽量圆润，避免纯方盒子。

火车必须是真正的 3D Group，并作为一个整体沿轨道运动。

---

## 五、列车与乘客循环动画

列车与乘客必须持续循环，不能进站一次后永久停止。

每轮约 42 秒，完整叙事为：

隧道驶出 → 匀速接近车站 → 平滑减速停车 → 站台侧车门打开 → 等候乘客依次上车 → 车门关闭 → 列车平滑加速离站 → 新乘客从入口走到站台候车 → 下一班列车到来。

- 至少 6 位具有不同衣服颜色的真实 3D 乘客，具备简单步行动作。
- 乘客在站台安全线内候车，列车停稳、车门打开后才能上车。
- 乘客需要走向对应车门并进入车内，不得直接在候车点消失。
- 站台侧车门必须可见地滑动打开与关闭；另一侧保持关闭。
- 全部乘客完成上车、车门关闭后，列车才能起步。
- 发车需平滑加速，列车沿轨道离开沙盘；不得悬浮驶入背景。
- 列车完全离开可见区域后才能重置到隧道内部，禁止可见的瞬移。
- 新乘客从站台入口走入，依次到达候车位置，不能整批凭空出现在站台中央。
- 复用列车、乘客和材质，不得每轮持续新增对象造成内存增长。
- 循环必须独立于摄影机，用户改变视角、缩放或平移不能打断循环，也不能被动画抢回视角。
- 页面进入后台时暂停时间推进，返回前台后自然续播。

## 八、隧道和山体

铁路一端进入绿色小山。

山体采用 stylized low-poly 形式。

不要做成单个半球。

通过多个不规则几何体组合形成自然山丘。

隧道入口应包含：

* 黑色洞口
* 混凝土或石质隧道框
* 隧道上方植被
* 两侧岩石
* 灌木
* 草地

隧道内部保持较暗，使火车从黑暗中驶出时有明显视觉反差。

* 白色路面标线

## 十、樱花树

樱花树是场景的重要视觉元素。

场景中放置大量樱花树，但避免机械式均匀排列。

樱花树结构：

* 简化树干
* 分叉枝干
* 多个不同尺寸的粉色花簇

花簇使用多个 SphereGeometry、IcosahedronGeometry 或类似低多边形几何体组合。

整体形成：

round clustered canopy

不要制作成单个粉色球。

每棵樱花树应有轻微随机差异：

* 高度
* 旋转
* 花冠大小
* 粉色色调
* 枝干角度

颜色以：

淡粉
浅粉
偏白粉
少量深粉

为主。

部分樱花树放在：

* 站台附近
* 道路边
* 山丘旁
* 住宅旁
* 沙盘边缘

## 十三、材质

整体采用简洁的 PBR 风格。

优先 MeshStandardMaterial。

不要大量使用高反射金属。

主要物体应有轻微磨砂塑料、模型玩具或建筑模型质感。

整体 roughness 较高。

metalness 较低。

玻璃区域可以提高透明感和反射感。

不要使用复杂纹理依赖。

尽量通过：

* geometry
* color
* roughness
* metalness
* lighting

表现视觉层次。

---

## 十四、灯光

灯光质量非常重要。

至少包含：

* AmbientLight
* HemisphereLight
* DirectionalLight

主 DirectionalLight 模拟春日下午阳光。

开启 shadows。

需要有：

soft shadows
contact feeling
clear depth separation

如果 Three.js 官方后处理可方便实现，可以加入：

* subtle bloom
* SSAO 或类似环境遮蔽
* FXAA / SMAA

但 Bloom 必须非常轻微。

不要做成霓虹效果。

---

## 十五、背景和气氛

不要使用复杂 HDR 环境背景。

使用干净的浅色背景。

推荐：

顶部浅蓝
中间接近白色
底部略带淡粉

形成柔和春日天空感觉。

可以通过 CSS background 或 Three.js shader/background 实现。

沙盘底部与背景之间应该有足够视觉分离。

---

## 十六、樱花花瓣

场景中增加明显可见但柔和的持续花瓣飘落。以约 360 片为目标，采用 InstancedMesh、Points 或其他高性能方案。

花瓣在山丘、铁路、站台、住宅和前景之间分布，保持景深层次。花瓣缓慢下降、左右漂移、轻微旋转，并有尺寸与速度差异。

不要做成暴风雪；不要快速闪烁、整批重置或明显遮住列车及站牌。可复用固定数量对象持续循环，移动端保持基本流畅。

## 十八、摄影机与默认视角

打开页面后立即允许用户自由观察，不播放强制自动运镜，不等待动画结束后才启用交互。

初始采用约 35～45 度俯视的三分之四全景。使用 PerspectiveCamera 和较长焦距减少透视变形，保留微缩模型摄影感。

## 十九、全景构图

全景清楚包含山丘、隧道、双线铁路、车站、住宅、樱花、道路与沙盘完整外形。手机竖屏也要合理调整初始距离。

## 二十、自由观察

用户从第一帧起即可连续旋转、缩放和平移，近距离观察列车、站台与住宅细节。列车和环境动画不得修改用户摄影机的位置或观察目标。

## 二十一、空间层次

从常见观察角度都应有前景、中景和背景，避免关键候车和上车区域被树冠或房屋完全遮住。

## 二十二、近景细节

近距离能看到乘客候车与上车、车门开关、车轮和转向架、站牌、长椅、售货机、电线及道口设施。

## 二十三、视角复位

双击画布或按 R 键回到默认全景。复位不得重启列车和乘客循环。窗口尺寸变化时更新投影与画布，尽量保留用户当前视角。

## 二十四、用户交互

使用 OrbitControls，打开 damping，从页面加载后立即启用：

- 鼠标左键拖动旋转。
- 滚轮缩放。
- 鼠标右键拖动平移。
- 移动端单指旋转，双指缩放和平移。
- 双击或 R 键复位。

设置合理但不过度限制的缩放与俯仰范围，允许靠近检查模型细节，默认不翻到沙盘底部。不要在自动列车动画期间禁用交互。

## 二十七、性能

目标优先保持流畅。

桌面端尽量接近 60fps。

移动设备也应该基本可用。

合理使用：

InstancedMesh
geometry reuse
material reuse

樱花花簇、枕木、石块、灌木等重复元素应尽量复用 Geometry 和 Material。

不要为每一个重复物体创建完全独立的材质。

控制：

* polygon count
* shadow map size
* postprocessing complexity
* particle count

但性能优化不能成为大量删除场景细节的理由。

## 二十八、响应式

窗口尺寸变化时正确更新：

camera.aspect
camera.updateProjectionMatrix()
renderer.setSize()

支持：

桌面
平板
手机

手机上调整 pixel ratio，避免高 DPR 导致严重性能下降。

## 二十九、禁止出现的问题

禁止最终效果像 Three.js 官方入门教程。

禁止：

* 大量纯色立方体
* 极度简化的建筑
* 一个方盒子代表火车
* 一条黑线代表铁路
* 一个粉色球代表樱花树
* 空旷场景
* 默认 OrbitControls 视角
* 默认灰色背景
* 默认网格辅助线
* AxesHelper
* GridHelper
* GUI 调试面板
* 性能监控面板
* Debug UI

最终页面中不能出现开发辅助元素。

## 三十、视觉优先级

如果开发过程中需要在功能之间做取舍，按照以下优先级：

1. 最终视觉完成度
2. 场景构图
3. 自由视角交互与多角度构图
4. 列车与乘客完整循环动画
5. 光照和阴影
6. 3D 模型细节
7. 环境丰富度
8. 微动画
9. 性能优化
10. 代码简洁程度

不要为了代码短而降低完成度。

不要为了“先跑起来”而停留在 prototype 状态。

需要继续迭代到画面明显具有成品感。

---

## 三十一、最终验收标准

完成以后请自己检查最终效果。

首屏必须立即具有视觉冲击力。

用户第一眼应该能够认出：

“这是一个精致的日本铁路樱花微缩模型。”

而不是：

“这是一些 Three.js 几何体。”

列车与乘客动画需要形成完整且持续重复的叙事：

火车从隧道驶出 → 经过道口 → 减速停站 → 开门 → 乘客依次上车 → 关门 → 加速离站 → 新乘客走入站台候车 → 下一轮进站。

最终画面应该具有：

* 明确的前景、中景、背景
* 空间层次
* 柔和阴影
* 丰富但不杂乱的细节
* 一致的色彩体系
* 日系微缩模型质感
* 明显的春季樱花氛围
* 始终可用的自由视角与流畅、克制的循环动画

完成代码后，不要只确认“可以运行”。

请从视觉效果角度主动检查：

* 场景是否太空
* 模型是否过于简单
* 火车比例是否合理
* 镜头是否穿模
* 近景是否有足够细节
* 樱花是否自然分布
* 光照是否过曝
* 阴影是否过硬
* 火车动画是否自然
* 默认全景及常见自由视角是否漂亮
* 列车停稳后才开门、乘客上完后才关门发车
* 新乘客是否自然走入，循环边界是否没有可见瞬移
* 多轮运行后对象数量是否稳定

如果存在这些问题，请直接继续修改代码，直到达到成品级效果。
