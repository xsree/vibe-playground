# 工艺流程可视化应用最终产品方案

本文档与 `MVP方案.md`、`最终产品技术方案.md`、`process-flow.schema.json` 和 `pendimethalin-process.test.json` 配套使用。新对话开始开发时，应先读取这些文件；其中测试 JSON 是产品功能和布局效果的首个完整验收样例。

## 1. 产品定义

本产品是一款面向工艺流程描述的轻量可视化编辑工具。用户输入自然语言工艺说明，系统自动识别物料来源、工艺设备、设备连接、分支流向和最终产品，生成带设备大致外形的可编辑流程图。

产品不定位为专业 P&ID、CAD 或工程设计审查系统，而是解决以下问题：

- 工艺描述只有文字，难以快速理解设备之间的关系。
- 手工绘制流程图耗时，且修改连接关系不方便。
- 通用流程图工具缺少反应釜、储罐、分离器等工艺设备外形。
- AI 可以理解文本，但生成的图片通常无法继续编辑。

产品的核心价值是：

> 将“AI 对工艺的理解”转化为“人可以继续编辑的数据和图形”，而不是生成一张不可修改的图片。

## 2. 产品目标

### 2.1 核心目标

- 从自然语言快速生成设备连接关系图。
- 显示设备大致形状，使图形比普通方框流程图更直观。
- 保证设备之间不重叠，管线尽量清晰。
- 支持用户修改 AI 生成的任何设备和连接。
- 保存可继续编辑的源文件。
- 导出适合汇报、说明和归档的图片或 PDF。

### 2.2 非目标

- 不自动生成可用于施工的完整 P&ID。
- 不替代工程设计人员进行安全审查。
- 不建立完整的设备选型和物性计算系统。
- 不覆盖阀门、仪表、联锁、管径和管线等级设计。
- 不追求与 AutoCAD、EPLAN 等专业工程软件功能对等。

## 3. 目标用户

- 需要理解或说明工艺流程的技术人员。
- 工艺、生产、研发和安全相关人员。
- 需要把实验或生产流程快速转换成图形的工程师。
- 需要制作工艺汇报材料的项目人员。
- 需要阅读工艺资料但不熟悉专业制图工具的用户。

## 4. 典型使用场景

### 4.1 文本生成流程图

用户粘贴分步骤工艺描述，系统生成设备、管线、原料入口、支路和最终产品去向。

### 4.2 导入结构化数据

用户或外部程序直接提供符合 Schema 的 JSON/YAML，系统跳过 LLM，直接生成流程图。

### 4.3 修改 AI 结果

用户发现设备类型、形状或连接关系不准确，可以直接修改，不必重新生成整张图。

### 4.4 补充缺失设备

用户可以从设备库拖入新设备，设置名称和位号，并把它接入现有管线。

### 4.5 制作说明材料

用户完成调整后，导出 PNG、SVG 或 PDF，用于文档、汇报或沟通。

## 5. 核心用户流程

```text
创建流程图
  ↓
粘贴工艺描述或导入 JSON/YAML
  ↓
AI 识别设备、物料和连接
  ↓
数据校验与规范化
  ↓
自动选择设备形状
  ↓
自动无重叠布局和管线路由
  ↓
用户编辑设备、管线和布局
  ↓
保存可编辑源文件
  ↓
导出 PNG / SVG / PDF
```

## 6. 功能方案

### 6.1 项目与文件

- 新建空白流程图。
- 从工艺文本创建流程图。
- 导入 JSON 或 YAML。
- 打开已保存的流程图文件。
- 保存完整的语义数据和布局数据。
- 另存为新文件。
- 自动保存到浏览器本地存储。

产品不需要复杂版本系统，但应避免因刷新页面导致当前编辑内容丢失。

### 6.2 文本解析

- 支持连续段落和编号步骤。
- 识别设备名称、设备位号和无位号设备。
- 识别物料来源、设备之间的输送、物料去向。
- 识别串联、并联、回收、排放、气相和水相支路。
- 识别 `A/B`、`A—E` 等设备组表达。
- 无位号设备自动生成随机内部 ID。
- 不明确的设备使用通用设备节点，不凭空补造位号。
- 解析完成后显示数据校验结果。

### 6.3 设备图形

- 每个设备由统一节点外壳和内部 SVG 图形组成。
- 显示设备位号、名称和可选数量。
- 聚合设备组显示 `×N`。
- 设备形状只表达大致类别，不追求工程制图精度。
- 未识别设备显示通用工艺设备形状。
- 用户可从形状列表中手动更换设备外形。

设备形状库按视觉家族组织：

- 反应釜与容器；
- 储罐与接收罐；
- 塔器；
- 管式设备；
- 分离与过滤设备；
- 换热与冷凝设备；
- 泵、计量和输送设备；
- 料仓和固体处理设备；
- 包装和末端设备；
- 原料、产品和外部处理系统；
- 通用未知设备。

### 6.4 管线

- 管线连接到设备端口。
- 移动设备时管线保持连接。
- 支持直线和正交折线。
- 支持手动增加、删除和拖动折点。
- 支持重新连接管线的源端或目标端。
- 支持显示物料名称。
- 支持按物料类型显示不同线型或颜色，但不能只依赖颜色表达含义。
- 支持主物料、进料、产品、气相、废水、回收、辅助介质等常见类别。
- 管线路由尽量避开设备节点。

### 6.5 自动布局

- 默认从左向右排列主工艺流程。
- 设备之间不得重叠。
- 原料和辅助物料放在主流程入口附近。
- 气相支路优先向上布置。
- 水相、废液和粉尘支路优先向下布置。
- 回收流可布置为返回上游或连接到明确的外部回用节点。
- 对断开的多个流程分量进行分区排列。
- 用户可以对整图或选中区域重新布局。
- 用户手动排好的位置不会因普通编辑自动重排。

### 6.6 编辑功能

- 单选、多选和框选。
- 拖动设备。
- 复制、粘贴和删除设备。
- 新建设备和设备组。
- 修改设备名称、位号、类型、数量和形状。
- 新建、删除和重新连接管线。
- 修改物料名称、物相和管线类型。
- 直线与折线切换。
- 撤销和重做。
- 适应视图和定位选中设备。
- 锁定节点，避免误移动。

### 6.7 数据编辑

- 提供结构化数据查看器。
- 支持 JSON 和 YAML 两种显示方式。
- 用户修改结构化数据后可重新校验并刷新画布。
- 画布修改同步回结构化数据。
- 校验错误应定位到具体节点、管线或字段。

### 6.8 保存与导出

- JSON：完整可编辑源文件。
- YAML：便于人阅读和手工修改的数据文件。
- PNG：适合快速分享和插入文档。
- SVG：适合无损缩放和后续排版。
- PDF：支持纸张尺寸、横向页面、缩放和分页。
- 导出时可选择是否包含背景、标题和图例。

## 7. 信息架构

产品采用单工作区结构：

```text
顶部工具栏
  新建 / 生成 / 导入 / 保存 / 导出
  撤销 / 重做 / 自动布局 / 适应视图

左侧面板
  工艺描述
  JSON/YAML
  设备库

中央画布
  设备形状
  物料管线
  选择和拖动交互

右侧属性面板
  设备属性
  管线属性
  图形设置

底部状态区
  校验错误
  节点数和管线数
  当前缩放比例
```

## 8. 关键交互原则

### 8.1 AI 生成结果必须可修改

生成完成后进入普通编辑状态，用户拥有最终控制权。不能把 AI 结果当成只读图片。

### 8.2 不让用户面对内部随机 ID

随机 ID 只用于数据连接。画布优先显示位号和设备名称。

### 8.3 重新生成不能轻易覆盖人工修改

最终产品可提供两种行为：

- 清空画布并重新生成；
- 将新的解析结果作为候选内容导入，由用户确认是否替换。

不需要复杂审计，但必须避免误覆盖。

### 8.4 自动布局是显式操作

首次生成时自动布局；此后只有用户点击“重新布局”才整体重排。

### 8.5 未知设备也必须能画出来

任何无法归类的设备，都显示通用设备形状和原始名称，不能因为没有专用图形而丢失。

## 9. 视觉表达原则

- 设备形状简洁、清楚，避免过度仿真。
- 标签优先显示位号，第二行显示名称。
- 聚合设备显示数量。
- 主流程线条最醒目，支路线条适当弱化。
- 气相、废水和回收流同时使用文字或线型区分。
- 设备选中、连接和错误状态应有清晰反馈。
- 画布支持浅色和深色主题。
- 图形导出时保证文字清晰，不依赖当前屏幕缩放比例。

## 10. 数据要求

产品以 `process-flow.schema.json` 为基础数据契约，核心内容包括：

- `nodes`：设备、来源、去向和分叉点。
- `edges`：物料管线。
- `layout`：节点坐标和管线路由。
- `settings`：布局及显示设置。

扩展原则：

- `equipmentType` 保持开放字符串。
- `shapeKey` 由形状注册表解释。
- 新增设备形状不要求修改核心 Schema。
- 扩展属性放在 `attributes` 中。
- 管线始终通过 `nodeId + portId` 连接。

## 11. 产品质量标准

### 11.1 正确性

- 不能丢失文本中明确出现的设备。
- 不能静默删除无法理解的设备或流向。
- 不明确的设备不能生成伪造位号。
- 管线不能引用不存在的设备或端口。
- 保存后重新打开，语义和布局应保持一致。

### 11.2 可读性

- 自动布局后设备不重叠。
- 标签不应被设备或其他标签大面积遮挡。
- 主流程应能从入口连续追踪到产品出口。
- 支路应尽量减少穿越主流程。
- 大型流程图应支持快速适应视图和定位设备。

### 11.3 可编辑性

- 所有 AI 生成设备均可删除、移动和修改。
- 所有管线均可删除、重连和修改样式。
- 移动设备不会破坏语义连接。
- 撤销和重做覆盖主要编辑操作。

### 11.4 稳定性

- 未知形状不会导致页面崩溃。
- 非法 JSON 不会覆盖当前有效画布。
- LLM 请求失败时，用户仍可继续编辑现有内容。
- 大图操作应保持可接受的响应速度。

## 12. 迭代路线

### 第一阶段：可运行 MVP

- 加载测试 JSON。
- 设备形状。
- 自动布局。
- 基础编辑。
- 保存 JSON 和导出 PNG。

### 第二阶段：文本生成闭环

- LLM 结构化输出。
- JSON Schema 校验。
- 错误修复和重新生成。
- JSON/YAML 双向编辑。

### 第三阶段：完整编辑体验

- 手动折点。
- 局部布局。
- 设备库搜索。
- 更丰富形状。
- SVG 和 PDF 导出。

### 第四阶段：可选增强

- 自定义形状。
- 从图片或文档辅助提取流程。
- 模板和示例库。
- 共享链接或轻量云端保存。
- 多语言设备名称和界面。

## 13. 最终验收场景

以一段从原料进入、经过多个设备、包含支路和回收流、最终进入成品库的工艺描述进行测试：

1. 系统能生成完整结构化数据。
2. 所有设备均以专用或通用形状显示。
3. 初始布局不存在设备重叠。
4. 主流程从左向右可追踪。
5. 气相、水相、回收和粉尘支路可识别。
6. 用户可以修正设备形状和连接关系。
7. 用户移动设备后管线不脱离。
8. 用户保存后能够恢复相同画面。
9. 用户能够导出清晰的 PNG、SVG 和 PDF。
10. 整个流程不要求用户掌握专业绘图软件。
