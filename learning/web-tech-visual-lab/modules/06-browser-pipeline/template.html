§ 06.01

关键渲染路径：重排 (Reflow)、重绘 (Repaint) 与 GPU 合成

Browser Rendering Pipeline
1. Layout 重排 (Reflow) 计算几何位置
→
2. Paint 重绘 (Repaint) 栅格化像素填充
→
3. Composite 合成 (Composite) GPU 图层合成
渲染测试节点
PIPELINE COST & CODE
管线耗时法则： 修改几何属性（width/height/margin/top）会导致浏览器重新计算整个渲染树的几何布局（Reflow），开销最大；使用 transform 和 opacity 可在独立合成层由 GPU 线程处理，完全跳过重排与重绘，保持 60fps 丝滑。
CSS 性能规则 
/* 🔴 昂贵操作：触发主线程重排 (Reflow) */
.box { width: 200px; left: 50px; }

/* 🟢 廉价操作：仅触发 GPU 合成 (Composite) */
.box { transform: translate3d(50px, 0, 0); }

SPECIFICATION & CODE
普通 <script> 行为： 浏览器遇到普通 script 标签时，立即停止 HTML 解析，直到脚本下载并执行完毕后才继续。现代工程推荐对依赖 DOM 的脚本使用 defer。
HTML 
<!-- 默认阻塞解析 -->
<script src="app.js"></script>

<!-- 异步下载，在 DOMContentLoaded 前按顺序执行 -->
<script defer src="app.js"></script>
§ 06.03

现代轻量弹出层：Popover API（原生 Light Dismiss）

HTML Popover Standard
点击按钮唤起气泡层，点击页面任意空白处原生自动收起 (Light Dismiss)

原生 Popover 弹出菜单

使用 HTML 原生 popover="auto"。无需写一行 JS 事件监听即可享受 ESC 退出与外部点击轻触收起（Light Dismiss）。

SPECIFICATION & CODE
Popover vs Dialog 区别： <dialog> 适用于强阻断模态框；popover 适用于非阻断式的轻量气泡卡片、操作菜单与 Toast，同样享有 Top Layer 顶层能力。
HTML 
<!-- 触发按钮 -->
<button popovertarget="my-menu">打开菜单</button>

<!-- 原生 Popover 容器 -->
<div id="my-menu" popover>
  <p>点击外部自动关闭 (Light Dismiss)</p>
</div>

§ 06.04 浏览器渲染管线触发阶段速查表

修改属性 触发管线阶段 主线程占用 优化建议
width, height, margin, top, left, font-size Layout (重排) $\to$ Paint (重绘) $\to$ Composite 🔴 极高（计算几何树与全局流式排版） 避免在动画帧循环中频繁修改
color, background-color, box-shadow, visibility Paint (重绘) $\to$ Composite 🟡 中等（像素栅格化着色） 尽量限定局部区域
transform (translate/scale/rotate), opacity Composite (仅 GPU 合成) 🟢 极低（独立合成层，由 GPU 直接变换） 现代高频动画与拖拽的黄金首选
