SECURITY POLICY & CODE
CSP 防御机制： 通过 HTTP 响应头 Content-Security-Policy: default-src 'self'，浏览器在内核层禁止执行任何未授权内联脚本与未知外部源请求，即使攻击者成功注入 HTML 字符串亦无法执行 JS 代码。 
# 生产环境推荐 CSP 响应头
Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-2726c7fbe44a'; object-src 'none';

PREFLIGHT SPECS & CODE
预检请求判定准则： 若请求方法为 PUT / DELETE，或携带自定义 Header（如 Authorization），浏览器必须先发 OPTIONS 请求验证服务器的 Access-Control-Allow-Methods 与 Access-Control-Allow-Headers。
HTTP 
# 服务器 OPTIONS 预检响应头
HTTP/1.1 204 No Content
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Authorization, Content-Type
Access-Control-Max-Age: 86400

SET-COOKIE SPEC & CODE
生产标准 Cookie 头： 存储鉴权 Token 或 SessionId 的 Cookie 必须同时声明 HttpOnly; Secure; SameSite=Lax (或 Strict)。
HTTP 
Set-Cookie: session_id=0xFA89BC; Path=/; Secure; HttpOnly; SameSite=Strict; Partitioned;
